## What landed (JARVIS)

- JARVIS principal `agent:jarvis` may **create** a Mail send-draft and **GET** that draft’s status (`mail.draft` / `mail.status`).
- Review pointer is Mail UI: `{mailOrigin}/#sendDraftReview?draft={draft_id}`. Humans approve/cancel/send there.
- JARVIS stores `draft_id`, `payload_digest`, Mail status, and a **card state**. UI is not authority.
- Card states (distinct):

  | Card | Mail status |
  | --- | --- |
  | `approval_required` | `needs_approval`, `approved` (still Mail-owned until Graph send) |
  | `sending` | `sending` without uncertainty |
  | `result_unconfirmed` | `sending` + `uncertain` or `failure_reason` |
  | `follow_up_needed` | `needs_clarification`, `failed` |

  `sent` / `cancelled` drop the card (`card_state` null); JARVIS still keeps the reference.

- `CORE5_INTEGRATION_ENABLED` remains default **off**.
- `mail.send` is **not** registered. Personal-connector `mail.configured` stays **false**.
- JARVIS has no approve/send/cancel methods; those throw `CORE5_MAIL_HUMAN_OWNED`.

## Still Mail-owned

- Human session, CSRF, origin, explicit confirm, payload digest, send flag, operator access key, `Mail.Send` scope.
- Agent Bearer on `/approve` or `/cancel` → `HUMAN_APPROVAL_REQUIRED`.
- Graph send, reconciliation, grok-bot token matching before JARVIS.
- List of all drafts (`GET /api/mail/send-drafts` without id).

## Token

`MAIL_INTELLIGENCE_JARVIS_DRAFT_TOKEN` (≥32 chars): draft + GET own draft only. Not used for approve/send.
