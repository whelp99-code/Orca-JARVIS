# Remote audit metadata retirement

Status: implemented and independently reviewed; not operationally activated. Backlog 07/12 remains
open; no default service registration, production migration or deletion performed.

Current-schema inspection found migration056's remote audit authorization tables
and guarded delete but no runtime adapter. The guard alone did not preserve the
event_id/event_digest uniqueness that original audit rows enforce. Removing those
rows without a retained identity would permit their later insertion again.

Migration081 adds immutable remote_audit_retired_events and three evidence/replay
guards. The retained record contains event ID/digest/type, outcome/reason, original
time and authorization ID. It omits separate principal, subject, correlation, request,
credential and assertion columns. Event IDs generated by the current approval
writer include the challenge ID, outcome and timestamp; retained event IDs are
therefore still linkable security metadata, not anonymous records. Event ID/digest cannot be reinserted into the
source table after retirement. Existing historical migrations are unchanged.
This preserves recorded identity/outcome, not full original assertion evidence or
physical SQLite erasure. The retained metadata still requires its own privacy policy.

createRemoteAuditRetentionAdapter(limit=100) is explicit host composition only.
It requires an enclosing transaction and a current claimed audit job with
remote-auth: key, matching policy cutoff, valid lease and a cutoff at least365days
before the runtime observation. Batch bounds are1–1000. Matching the existing SQLite LIKE guard, only
remote.% rows (including ASCII case variants) strictly older than cutoff qualify. Source selection orders by
time and event ID. Local/memory audits and cutoff-equal records are preserved.

Within the same RetentionRuntime transaction, the adapter records a digest-bound
applying authorization, copies minimal evidence, deletes source rows, and marks
authorization completed. RetentionRuntime checks current lease/time again before
committing its job receipt. An exception rolls back all adapter writes. Counts
refer to the selected eligible batch, not the whole audit table. A completed job
means that batch completed; further batches require additional explicit jobs.
A zero-row batch records zero counts without creating an authorization.

The adapter is trusted host code, not an independent public authorization API.
Direct arbitrary SQLite writes are outside its trust boundary; source guards add
evidence binding but do not replace the runtime clock, owner or transaction checks.
Credential retirement and indefinite credential tombstones remain separate.
Service scheduling and an operator-facing historical audit reader are not included.
